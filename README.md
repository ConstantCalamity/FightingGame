# FightingGame
a fighting game

## Setup

1. Install [Unity Hub](https://unity.com/download) and the Unity editor **6000.3.27f2** (Unity 6.3 LTS).
   Everyone on the project should use this exact version.
2. Install [Git LFS](https://git-lfs.com/) and run `git lfs install` once. Art, models and audio are stored with LFS.
3. Clone the repo, then in Unity Hub choose **Add → Add project from disk** and select the repo folder.

The project uses the Universal Render Pipeline (URP) and the Input System package.

## Playing

Open **Fighting Game → Open Fight Scene** in Unity and press Play. Pick fighters and a stage on the select screen.

| | P1 (keyboard / gamepad) | P2 |
|---|---|---|
| Move | A / D | ← / → |
| Jump | W | ↑ |
| Block | S | ↓ |
| Light | J | , |
| Heavy | K | . |
| Special (meter) | L | / |

`2` toggles P2 between CPU and human, `R` restarts the match, `Esc` returns to character select,
`F1` (or the on-screen button) shows hitboxes.

### Blocking and parrying

- **Parry**: start blocking within 0.15 s of a hit landing. The attacker is staggered, you gain 25 meter and
  some guard back, and the game briefly freezes and slows down. Re-blocking within 0.35 s of letting go does
  not arm a parry, so mashing block doesn't work.
- **Guard** (the bar under health): it drains while you hold block, faster the longer you hold
  (`1 - e^(-t/2)`), and drains further with each blocked hit. Blocks held for longer also take more chip
  damage and more push. If guard empties, your guard breaks and you're stunned for 1 s. Guard refills
  once you stop blocking.

### Characters

- **Caedryn, the Ashbound Knight** — slow, heavy greatsword. *Cleave* (diagonal slash), *Grave Slam*
  (overhead slam with armor during its startup), *Ashen Wave* (ground-travelling fire, jump over it),
  *Plunging Strike* in the air.
- **Isolde, the Thornwall Blade** — fast, long-reaching left-handed rapier. *Thrust*, *Fleche* (lunge that
  travels forward), *Throwing Knife* (fast, cheap projectile), *Falling Cut* in the air.

Move timing, damage and hitboxes live in `Assets/_Game/Data/Movesets.json`, which both the game and the
Blender animation scripts read.

## Art pipeline

Characters and maps are generated by Python scripts run in Blender 5.2 headless — see
`Tools/Blender/CONVENTIONS.md`. Typical loop for a character:

```
blender -b --factory-startup -P Tools/Blender/build_corvin.py      # model, materials, rig, weights
blender -b --factory-startup -P Tools/Blender/bake_character.py -- Corvin   # decimate, UV, bake 4K textures
blender -b --factory-startup -P Tools/Blender/anim_corvin.py       # animations, contact sheets, FBX export
```

Then in Unity run **Fighting Game → Rebuild Fight Scene**, which imports the FBX, builds materials and
registers characters and maps. Source `.blend` files are in `ArtSource/`.

## Online versus (two devices)

Use the same Windows build on both computers. On the character select screen's ONLINE VERSUS panel:

1. Player one picks both fighters and the stage, chooses **Host Game**, then copies the join code.
2. Player two enters that code and chooses **Join Code**.
3. The match starts when the second player connects. The host plays player 1 (left); the guest plays player 2 (right).
4. Both players use the P1 keys on their own machine: A/D move, W jump, S block (tap to parry), J light, K heavy,
   L special (or a controller).
5. The host can press R to restart or Esc to go back and change fighters/stage. **Leave room** ends the
   connection and returns to the select screen.

The project is linked to the FightingGame Unity Cloud project in khatrin2018. Multiplayer Services 2.4.1 and Netcode for GameObjects 2.7.0 use encrypted Relay connections, anonymous player authentication, and a maximum of two players. No router port forwarding is needed. Relay service usage is subject to the organization's Unity service quotas and pricing.

The host simulates combat. The guest sends buffered inputs; the host sends fighter state (pose, health, meter, guard), projectiles, timer, round state and the hits, blocks, parries and guard breaks since the last update at 30 Hz, and the guest replays those as sparks and sounds. This first version does not implement rollback/prediction or host migration: the guest feels network latency, and losing the host ends the match. A new room creates a new code. Offline CPU/local modes remain available.

### Validation

Build with **Fighting Game > Build Windows (dev)**. Test with two copies on separate devices and networks, including invalid codes, a third player attempting to join, host departure, guest departure, and rehosting. Same-machine testing verifies Relay connectivity but does not replace a real two-network latency test.

Development builds also accept `-network-smoke -host-code-file <path> -network-report <path>` for an automated host, or `-network-smoke -join-code <code> -network-report <path>` for a guest that walks toward the host and attacks. These tests exit after 40 seconds and write match state to the requested report path. Do not use the same report file for both processes.
